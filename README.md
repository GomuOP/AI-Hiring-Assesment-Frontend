# AI Hiring & Assessment Platform — Frontend

Next.js app for the AI hiring platform: recruiters configure and launch AI-generated assessments, candidates complete a proctored online test, all backed by the [Express/MongoDB API](../AI-Assessment-Hiring-Backend).

Live at: `https://aihiringassesment.vercel.app`

## Tech stack

| Concern | Choice |
|---|---|
| Framework | Next.js 16 (App Router), React 19 |
| Styling | Tailwind CSS 4 |
| In-browser AI proctoring | TensorFlow.js + `coco-ssd` object-detection model |
| Markdown rendering | `react-markdown` + `rehype-raw` (JD previews, rubrics) |
| Icons | `lucide-react` |

## Environment variables

| Var | Purpose |
|---|---|
| `NEXT_PUBLIC_API_URL` | Base URL of the backend API (e.g. `https://ai-hiring-assesment-backend.onrender.com`) |

## Pages & flows

### Recruiter flow
| Route | Purpose |
|---|---|
| `/auth/signup`, `/auth/login` | Recruiter or candidate account creation/login |
| `/admin/dashboard` | List of the recruiter's job descriptions, upload a new JD |
| `/admin/setup/[jdId]` | Configure assessment: section weights/time/question counts, difficulty split, number of question sets, resume-match threshold, pass cutoff, instructions, evaluation rubrics, start/end time window; triggers AI question generation and produces the shareable assessment link |
| `/admin/processing/[jdId]` | Progress view while the JD is being parsed / questions generated by Gemini |
| `/admin/dashboard/[jdId]` | Candidate list for a JD with status, scores, filters |
| `/admin/candidate/[id]` | Full candidate detail: resume analysis, per-section answers & AI feedback, proctoring event timeline, final pass/fail decision override |
| `/profile` | Recruiter account profile |

### Candidate flow
| Route | Purpose |
|---|---|
| `/assess/[link]` | Entry point from a shared assessment link — multi-step onboarding: **email + OTP verification → webcam photo capture → consent** |
| `/assess/[link]/resume` | Resume upload, shows AI match score/result |
| `/assess/[link]/instructions` | Pre-test instructions and proctoring rules |
| `/assess/[link]/test` | The timed assessment itself — objective (MCQ), subjective (free text), and programming (code editor + run/submit against Judge0) sections, each with its own timer; this is where proctoring runs live |
| `/assess/[link]/complete` | Post-submission confirmation |
| `/candidate/dashboard`, `/candidate/profile` | Candidate's own assessment history and profile |

## In-browser proctoring (`src/hooks/useProctoring.js`)

Runs entirely client-side during the test:
- Loads a TensorFlow.js `coco-ssd` model in the browser and periodically samples the webcam feed to detect `person` and electronic-device (`cell phone`, `laptop`, etc.) classes — flags **multiple people in frame**, **no face detected**, and **phone/device detected**.
- Browser-level signals tracked alongside: tab switches, window blur, fullscreen exit, dev tools opening, copy/paste/right-click attempts, and idle time.
- Every event is POSTed to the backend (`/api/assessment/proctoring/event`) with a severity level, building the integrity record a recruiter reviews later — no video is streamed to the server, only detection events and periodic snapshots.

## Local development

```bash
npm install
echo "NEXT_PUBLIC_API_URL=http://localhost:5002" > .env.local
npm run dev   # http://localhost:3000
```

## Deployment

Deployed on **Vercel** (Hobby tier, no card required). Set `NEXT_PUBLIC_API_URL` to the deployed backend's URL in the Vercel project's environment variables — it's a build-time variable, so redeploy after changing it.
